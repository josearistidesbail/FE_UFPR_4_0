## Tooling notes

- **S9.6:** the LaunchPad now sits on TOP; J20–J23 are `PinHeader_2x10` on F.Cu. `tools/board_layout/place_s9.py` reproduces the whole placement (370/370) — re-run it rather than hand-moving blocks; `add_lp_shadow.py` redraws the LaunchPad shadow on `Dwgs.User`. `kicad-cli pcb export ipcd356` checks pad nets against `golden.net`. Moving footprints by file edit is safe only with unchanged rotation.

- KiCad **10.0.5**; MCP server for schematic/PCB editing, ERC/DRC, BOM/gerber export, `snapshot_project`.
- `kicad-cli sym export svg` / `fp export svg` is the fastest way to prove a library actually parses — use it after any hand-edit of `.kicad_sym` / `.kicad_mod`.
- Datasheets via WebFetch/WebSearch (RM44AC, 6PS04512E43W39693, LA 100-P, TC4468, LAUNCHXL-F28379D).
- Temp exports go to the session scratchpad, not the project directory.
- **Never trust a hand-generated `.kicad_sch` until `kicad-cli sch export netlist` agrees with a golden baseline.** KiCad fails silently on a malformed token (it drops the rest of the sheet and still exits 0), and its connectivity rules are stricter than they look — see the four S7.5 behaviours in the Decision Log. The generator scripts and the checker live in the session scratchpad; the invariant they enforce is **149 nets / 745 nodes, node sets identical**.
- `kicad-cli sch erc --severity-all` groups some sub-sheet violations under the root's section — read the coordinates, not the section header, to attribute them.
- **PCB session workflow (S9):** MCP `sync_schematic_to_board` imports the netlist (equivalent of F8); `batch_move_components` places (flip with `layer: "B.Cu"` — reported as rotation 180, geometry correct); `place_component` with `boardPath` + `FE_UFPR_4_0:` prefix adds library footprints. **Edge.Cuts by file edit** — `replace_board_outline`/`clear_board_outline` crash on the SWIG backend. **After ANY external edit of the `.kicad_pcb`, call `open_project` before the next MCP write** or its auto-save is refused and the change lives only in memory. The gate is `kicad-cli pcb drc --severity-all --format json`; the MCP `check_courtyard_overlaps` is bounding-box only (phantoms on L-shaped courtyards) and a *malformed* courtyard is skipped by KiCad's overlap test — DRC must report zero `malformed_courtyard` before its overlap result means anything.
- **Render and look** applies to the board too: `get_board_2d_view` (file mode) after every placement pass; the KiCad GUI holding the project open (`~*.lck`) does not see file-level edits until the board is reloaded.
- **Render and look** after any regeneration: `kicad-cli sch export svg` → `rsvg-convert` → crop. The netlist gate cannot see labels drawn over parts or scrambled notes (S8 found both, a session late).
- **KiCad label/field orientation rules** (measured S8, encoded in `layoutlib`/`sheetedit`): a vertical global label's *justify* picks the side of the anchor (`right` = hangs below); field justification is transformed by the symbol's mirror/180° rotation; `(text …)` file order changes on every regeneration, so address notes by content.
- `dump.py`/`conncheck` reported both S8 sheets as "1 net, 87 unlabelled pins" while `kicad-cli` proved them fully connected — a known false alarm, still not the gate.
- **TE `DocumentDelivery` rate-limits**: a 222-request burst earned a ~1 h 403 for this address. Probe a few names with a pause between them. A missing drawing answers HTTP 500 + HTML.
- **JLCSearch**: `/api/search?q=<LCSC or MPN>` gives `is_basic`/`is_preferred`/stock/price for ICs too (the category endpoints only cover passives), but the two disagree on stock — treat both as snapshots. **Python `urllib` gets HTTP 403** (User-Agent) — use `curl` (`tools/fab/jlc_verify.py`). `/api/search` does not index every part (`C25804` 10 k 0603 is missing); `resistors/list.json?lcsc=N` honours the filter, `capacitors/list.json?lcsc=` ignores it and returns unrelated rows.
- **`kicad-cli sch export bom`** in zsh: `--fields '…,${QUANTITY},${DNP}'` must be single-quoted or the shell empties them (the export then silently lacks the column); references come grouped as ranges (`C16-C18`). `kicad-cli pcb export pos` with no aux origin uses the page origin with Y negative-down (KiCad convention, accepted by JLC's CPL importer).
  ⚠ **`/api/search` silently returns `{"components":[]}` for passives that exist** (2026-09-17: `C25804`,
  10 k 0603 Basic with **37 M in stock**, and its MPN `0603WAF1002T5E`, both come back empty). The search
  index is incomplete. **Never conclude a part is delisted from `/api/search` alone** — cross-check
  `/resistors/list.json?package=0603&resistance=10000` (or `/capacitors/list.json`), which is authoritative
  for passives and returns `is_basic`/`tolerance_fraction`/`stock`/`price1`.
  Also: **`urllib` gets HTTP 403** — the endpoint requires a `User-Agent`. Use `curl`, or set the header.
- The MCP `batch_add_components` does not add the library symbol's `LCSC` property to every instance — `vio_layout.py` sets it for its own parts; check `grep -c '(property "LCSC"'` equals the symbol count after any MCP add.
- **3D render / STEP (2026-09-17):** `kicad-cli pcb render --quality high --perspective --rotate "-40,0,30" --zoom 1.15 -o <scratch>/iso.png FE_UFPR_4_0.kicad_pcb` renders in ~1 s (`--side top|left|front`, `--floor` for shadows); `kicad-cli pcb export step -o <scratch>/asm.step` gives the MCAD assembly. Both need `kicad-library-3d` installed — without it every `${KICAD10_3DMODEL_DIR}` reference silently resolves to nothing and the board renders bare (it did until 2026-09-17). Project bodies: `3dmodels/` via `tools/board_layout/gen_3d_models.py` (needs cadquery: `uv venv cqenv && uv pip install -p cqenv/bin/python cadquery`, ~2 min; keep the venv in the scratchpad) and `attach_3d_models.py`. **Model space has y UP** — negate every footprint y when building a body; z = 0 is the board top; the model follows the footprint's rotation/side by itself. `(opacity 0.45)` goes right after the model path.
- **The board is normally OPEN in the KiCad GUI while you work** (`~FE_UFPR_4_0.kicad_pcb.lck` present, and a live diff showed footprints changing under the session on 2026-09-17). Never write `FE_UFPR_4_0.kicad_pcb` externally while the lock exists — pcbnew will overwrite it on the user's next save, or the user loses their unsaved work on reload. Library files and new files are safe; for board edits, verify on a scratchpad copy and hand the user the script to run after they close the editor.
- **KiCad 10 board pads carry `(net "name")` with no net number** — regexes written for the older `(net N "name")` match nothing. `pcbnew` under Python 3.14: `board.Drawings()` iteration raises `'SwigPyIterator' object has no attribute 'next'`; `GetFootprints()` / `Pads()` work, so read `gr_line` / `gr_arc` from the file text instead.
- **🛑 Where the "restores" come from (found 2026-09-23).** Two mechanisms, neither a Claude session:
  (1) **KiCad 10 Local History** (`kicad_common.json` → `local_history_enabled`) keeps a git repo in `.history/`
  with the 14 project files; a *Restore* from that panel copies the live files to `_restore_backup_<local time>/`
  and checks the old versions out. That repo had been **corrupt since 2026-08-25** (`main` → empty object,
  `git fsck` fails), so both restores (2026-09-17 15:06, 2026-09-22 22:07 — KiCad open, no session running)
  wrote the S7-era `.kicad_sym` and the schematic-freeze-era `.kicad_pro`. **Disabled 2026-09-23**, repo
  renamed `.history_corrupt_2026-09-23/`, both folders ignored. Never restore from that panel; git is the history.
  The `_restore_backup_*` folders hold the *good* pre-restore files — that is how the library was recovered.
  (2) **MCP backend stale project model** (`python/utils/project_settings_guard.py` docstring): the long-lived
  backend does not re-read a hand-edited `.kicad_pro`; its next board save writes the stale model back. The guard
  now preserves `net_settings` but deliberately lets `board.design_settings` through — the `rules` block that
  reset twice. **Restart the MCP server after any hand edit of `.kicad_pro`** before an MCP board write.
- **🛑 `pcbnew.SaveBoard()` writes the `.kicad_pro` too (2026-09-23).** It saves `<stem>.kicad_pro`/`.kicad_prl` next to the board, from the design settings in memory — KiCad defaults if the board was loaded from a scratch name with no project beside it. Never `SaveBoard` into the project directory; load from a same-stem copy with the `.kicad_pro`/`.kicad_dru` alongside, save to scratch, copy back only the `.kicad_pcb`, check the `.kicad_pro` md5. A SaveBoard round-trip of an untouched board is byte-identical, so `diff` shows exactly a script's changes. Details: `DECISION_LOG.md` 2026-09-23.
- **pcbnew from Python 3.14 (KiCad 10.0.6):** collections (`Tracks()`, `Drawings()`, `GraphicalItems()`) are not iterable (`SwigPyIterator.next` missing) but `len()` + `coll[i]` work; items come back as `BOARD_ITEM` (use `pcbnew.Cast_to_PCB_TEXT` etc.). `GetPosition()` returns a *reference* — copy it before moving the item. `pad.GetEffectiveShape()` and `fp.GetCourtyard()` are cached objects that `fp.Add()` invalidates (segfault if you kept them) — re-fetch or copy (`SHAPE_POLY_SET(poly)`). Anything you `fp.Add()` needs `item.thisown = False`. Silk/body geometry: `fp.TransformFPShapesToPolySet(poly, layer, 0, 5000, ERROR_INSIDE, includeText, includeShapes, False)` and `SHAPE_POLY_SET.Collide(SHAPE_RECT(bbox), clearance)`. `kicad-cli fp export svg` needs the output directory to exist. `GetBoundingBox()` of a 1.0 mm text is **1.7 mm tall** (ascender/descender room), not 1.15 — budget placements from the real box. A **second `fp.Remove()` of a footprint text in one session leaves every later proxy an unresolvable `SwigPyObject`** (`'SwigPyObject' has no attribute 'IsVisible'`) — re-use the text object (`SetText`/`SetPosition`) instead of removing it (`tp_db37_labels.py`).
- **A restore rolls back more than the file you meant (2026-09-17):** the 15:06 restore that regressed `.kicad_pro` also replaced `FE_UFPR_4_0.kicad_sym` with a copy lacking the six S8 symbols — silently, because KiCad keeps working from the schematic's embedded `lib_symbols` cache. It also reset `board.design_settings.rules` to KiCad defaults (hole-to-hole 0.25, annular 0.10, clearance 0 — below JLC). After any restore / `discard_or_reload`: diff the whole `board.design_settings` and `net_settings` blocks of `.kicad_pro` against the last good commit (`python3 -c "import json…"`, see the pre-S10 decision entry), ERC must show no `lib_symbol_issues`, `kicad-cli sym export svg` must produce 59 unit files, and the `(class …)` counts must read 61/4/23/9/5/117.
- **`kicad-cli pcb drc --schematic-parity` is the only check that compares footprint pad names with symbol pin names.** J2's `SH`/`SH` vs `G1`/`G2` mismatch survived six sessions of ERC, DRC and IPC-D-356 because none of those compare names. It also reports `extra_footprint` for the H* mounting holes unless they carry the *Not in schematic* attribute.
